## 3. Phase E — self-heal + self-create (the milestone)
Research first (37+ sources): self-heal is safe/solved; self-create needs a human
gate; full self-deploy is a documented foot-gun (reward-hacking generalizes to
sabotage when an agent writes AND grades/ships its own code). Built to the rule:
**heal within hard limits, propose improvements, never ship to self.**

- **E1 — resilience floor** (`argo_guard.py`): retry w/ capped backoff+jitter
  (transient only), per-provider circuit breaker, and a hard persisted daily
  call budget. Every model call runs budget -> breaker -> retry. Structurally
  prevents the runaway-loop cost class.
- **E2/E3 — gated self-heal** (`reregister_webhook`, `refetch_signals`), gated by
  `ARGO_HEAL_LEVEL`. L0 report-only default; **L1 confirm-in-chat** (Argo proposes,
  you reply CONFIRM, it acts). Idempotent/non-destructive only; no restart/delete.
- **E4 — propose-only self-create** (`propose_change`): Argo drafts a new
  capability/fix and opens a GitHub PR via a **separate PR-only token**
  (ARGO_PROPOSE_TOKEN), never the serving token; branch-only, never self-merges.

## 4. Schedules + feeds as DATA (so self-create stays safe)
Decided NOT to grant the propose token GitHub **Workflows** access (a merged
workflow runs with all secrets -> exfiltration risk). Instead:
- **Schedules as data** (`data/schedule.json` + `argo_scheduled.py` + a single
  hourly `argo-schedule.yml`): new scheduled deliveries are a data edit Argo can
  propose, no workflow editing. Old per-job crons removed to avoid double-fire.
- **Feeds as data** (`data/feeds.json`, loaded by `fetch_signals` with a
  fallback): add a feed via a tiny data diff, not a Python rewrite. Feed hosts
  auto-derive into the fetch allowlist on merge (the merge stays the security
  gate). Added the Show HN feed.
- **`verify_feed` tool**: vet a feed on ANY host (SSRF-guarded, narrow — reports
  only is-it-a-feed + item count) to fix the new-host chicken-and-egg, so Argo
  can vet a brand-new source before proposing it.

## 5. Activating it (the long debug, honestly logged)
Getting the live loop working surfaced a chain of real issues, each fixed:
- chat self-call **deadlock** (tool call looped into the same blocked worker) ->
  webhook now processes in a background thread, returns 200 immediately.
- read path 404 -> `github_read_file` uses `GITHUB_TOKEN`, which wasn't loaded
  (propose token is separate by design).
- **PR path 403** -> the token had Contents:read but not write. Argo diagnosed
  this itself ("403 on branch creation, token lacks write, a permissions issue I
  can't fix from here") — exactly the honest behavior we wanted.
- Fix: regenerate the fine-grained token with Contents: read+write + Pull
  requests: write (NO workflows), set as both GITHUB_TOKEN and ARGO_PROPOSE_TOKEN.

## 6. PR #1 — the loop closes
With the write-capable token, Argo: verified arXiv cs.SE (38 items) -> read
`data/feeds.json` -> drafted **PR #1 "Add arXiv cs.SE feed"** (clean, +2/-1, one
file, branch-only) -> said "I drafted it, you merge." Reviewed (surgical, valid
JSON, real feed) -> **merged.** cs.SE is now in `main`; Argo gains it on the next
deploy. Generator (Argo) / reviewer / merger (human) are three separate parties,
exactly as the safety design requires.

## State at end of session
Argo is a closed-loop autonomous agent with a deliberate human gate: heals itself
(on CONFIRM), proposes new tools/feeds/schedules (PRs you merge), runs behind
hard cost caps, and can never merge, deploy, or edit workflows itself. Proven
end-to-end via PR #1.
