## 1. Conceptual foundation
- **`ARGO_ARCHITECTURE.md`** — Argo as a **decision engine** (not a chatbot).
  Loop: Observe → Interpret → Select → Recommend → Reflect. Objects: Bet →
  Project → Artifact → Review, optimizing for **energy** (how much Yiya wants to
  build), not correctness. `/another` = recommendation *search*.
- **`ARGO_V2.md`** — reframed as **insight engine first, bet engine second**.
  Loop: Signal → Observation → Insight → Bet → Energy → Artifact. "The product is
  one project, not a report."
- **`ARGO_V2_MIGRATION.md`** — smallest path V1→V2: generate observations first,
  prove insight generation before machinery.
- Held throughout: **SEAS asks "what is true?"; Argo asks "what should I do next?"**

## Gotchas learned
- Secrets set by user in their own terminal, never in chat.
- Telegram webhook breaks silently on domain/token change (now self-heals).
- Newline inside a secret → illegal-header "Connection error"; set single-line.
- API keys `.strip()`-ed in code.
- `data/signals.json` gitignored (transient); `argo_projects.json` / `argo_chat.json`
  / `argo_seen.json` are durable.
