## TL;DR
Argo can now improve itself from two directions. The **self-improvement loop**
(PR #10, merged + live) reacts to failures: operational incidents persist to a
ledger, a daily diagnose pass names the likely cause, and a human FIX reply turns
it into a tested PR that is verified by CI and confirmed by a post-deploy quiet
window. The new **frontier-evolution loop** (PR #11, open) reacts to the frontier
itself: it watches release feeds for Argo's own stack, maps anything new against an
honest stack manifest plus the live capability inventory, nudges at most one
upgrade lever a day behind an EVOLVE/SKIP gate, rehearses big bets with Argo's own
adversaries, drafts the change through the existing propose machinery (human merge,
always), and records a **dated prediction that is armed when the PR merges and
scored against the incident ledger when due** — the prediction-scoring loop the
V3 docs deferred, finally built. Research note from the session, live-verified: as
of June 2026 no production system publicly auto-adopts model/API releases this
way. 196 tests green on the PR branch.

The week-one plan is dogfood: three pre-seeded levers (structured outputs, prompt
caching, the Batch API) flow through the full pipeline one nudge per day, so the
loop's first upgrades are changes to itself that reality then grades.

## 1. Self-improvement loop, live (PR #10)
`src/argo_incidents.py` + `src/argo_diagnose.py` (new), `propose_change` hardened.
Failures used to evaporate to stdout; fixes used to be claimed, not proven. Now:
every operational failure rolls up into a fingerprinted ledger; a daily funnel
(four free gates before one guarded model call: min 3 recurrences/24h, dedupe
against open proposals, max 1 nudge/day, pick the worst) sends one honest nudge —
reply FIX to get a PR that must carry a reproduction test and pass an AST
wire-check, or IGNORE to mute. CI is polled (`verify_open_proposals`), and a merged
fix is only called resolved after a 24-hour quiet window with zero recurrence
(`confirm_deployed`) — the ledger itself is the post-deploy verifier, so a fix that
didn't hold reopens automatically.

## 2. The frontier-evolution loop (PR #11)
`src/argo_evolve.py` + `src/argo_predictions.py` (new), `data/frontier_feeds.json`
+ `data/stack_manifest.json` (new, committed). The mirror image of diagnose: not
"what broke?" but "what did the frontier just unlock?"

- **Watch:** release Atom feeds for the stack (SDKs, claude-code, MCP servers) with
  an own-namespace seen-store (same identity/attempt mechanics as the tripwire).
- **Map:** ONE guarded Sonnet call a day, fed the new items, the stack manifest
  (an honest machine-readable self-description, including the features Argo does
  NOT use yet), the live capability inventory, and the self/world belief stores.
  Output: one lever or NONE.
- **Gate:** at most one nudge a day; EVOLVE/SKIP in Telegram, exactly like
  FIX/IGNORE. SKIP mutes a feature for a month.
- **Argue:** a `major` lever must survive Rehearse — the same three adversaries +
  judge that stress-test user projects now attack Argo's own upgrade bets. A KILL
  is final (60-day mute).
- **Draft:** the existing propose path opens the PR (repro-test gate, size caps,
  PR-only token). Argo still cannot merge anything.
- **Score:** an adopted lever records a dated prediction that is **armed at merge
  time** (the clock starts when the change is live, not when it's discussed) and
  scored against the incident ledger when due — moving the world-model belief by
  the ±0.20 prediction step, the strongest legitimate confidence mover, exercised
  for the first time. Unknown metrics stay unscored; unscorable benefits stay
  belief evidence. Honesty over coverage.

New guardrail for both loops: `PROTECTED_PATHS` — a proposal that touches
`.github/` (CI, the thing that proves fail→pass) or `src/argo_guard.py` (budgets
and breakers) is refused before any GitHub write. The loops cannot modify their own
rails.

## 3. The placement gap: the scheduler never lived where the data does
Found while wiring the frontier command: production scheduling ran **only** in
GitHub Actions — where the volume-backed ledgers are gitignored and therefore
empty. Diagnose had been structurally inert in production since it merged; nothing
on Railway ran scheduled commands at all. The lesson, now a finding: a scheduled
behavior is only real when **trigger, filesystem, and consumer are the same place**
— call-site wiring proves nothing about placement.

Fix: `argo_scheduled.fire_due()` (factored single pass with a command filter and a
pluggable dedupe store) + `local_loop()` — the webhook now runs the volume-bound
commands (`diagnose`, `frontier`) in a daemon thread against its own filesystem,
with its own dedupe state (the Actions runner commits `schedule_state.json` into
the repo, so sharing it would let an inert Actions fire consume the webhook's
window for the day). Actions keeps the delivery jobs (project / watch / reflect).
The frontier schedule entry ships `enabled: false` until one live EVOLVE
round-trip is verified.

## 4. Argo reads files now
`argo_webhook._handle_document` (d9345d8): any file sent over Telegram is
downloaded, saved durably under a volume-backed `FILES_DIR`, and actually read —
PDFs as native document blocks, text-like files inline (clipped), other binaries
acknowledged honestly. Previously only images were handled; everything else fell
through the text guard and was silently dropped.

## 5. Capability gaps become PRs, not shrugs
The system prompt now routes "Argo, do X" where X isn't yet possible through four
explicit branches: **buildable** → call `propose_change` in the same turn and open
the PR that adds the capability (plain about the human merge); **not feasible** →
refuse with the exact missing piece named, checked before claimed ("a vague 'I
can't' is never acceptable"); **by design** → safety limits are explained, never
"fixed"; **config** → name the exact env var. Locked by tests, including a
regression pin for a literal-brace `.format()` bug caught during the session.

## 6. Meta-lessons from three parallel sessions on one tree
- **Select your own hunks positively, never subtractively.** One session's
  hunk-split dropped the peer hunks it *knew about* and unknowingly swept another
  session's webhook hunks into main without their dependencies — dangling
  references that survive because the import is lazy and the thread is a daemon.
  Merging PR #11 heals main; the technique memo now says: keep only hunks you
  authored, and grep the staged diff for symbols you didn't write.
- **Test the staged snapshot, not the working tree.** `git checkout-index` +
  running the suite in the exported tree caught a real staging-dependency gap
  before it became a broken commit (and its known blind spot — lazy imports and
  daemon threads don't fire under unittest — is now written down).
- A reminder that the gates are the product: the upgrade loop's most important
  property is not what it can do, but what it structurally cannot — merge, touch
  CI, touch the budgets, or claim an outcome reality hasn't graded.
