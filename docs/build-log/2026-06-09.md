## 2. The persistence bug behind the "memory bug"
The tripwire's seen-store only persists because the hourly Actions run commits it
back to the repo. The release prep gitignored and `git rm`'d it — so `git add`
no-op'd silently and the store reset to empty on every run, re-alerting the same
stories for weeks. Fix: un-ignore `data/argo_seen.json` + `data/schedule_state.json`,
split the multi-path `git add` (one path per line — a single command aborts and
stages nothing if any path is ignored), and canonicalize the dedup key
(scheme/query-insensitive URL + normalized title) so the same story syndicated
through two feeds collapses to one alert.

## 3. Phantom sends get a deterministic route and honest acks
"Said sending, nothing landed": the model narrated a project send without firing
the tool. Fixes: an explicit proposal route in the webhook (mirrors SELECT /
REHEARSE — "give me a proposal" / "add my idea: X" call the pipeline directly,
deterministically); per-tool-call telemetry from `chat_with_mcp` so every fired
tool is one log line and a phantom is visible at a glance; a conversational
backstop that corrects the claim when no project tool actually fired; and
non-committal acks ("on it") that stop promising artifacts the turn might not
produce. The reply-context helper from PR #6 was finally wired in — the "written
but never imported" discovery that became a standing verification rule.
