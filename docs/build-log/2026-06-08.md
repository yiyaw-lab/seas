# Build Log — 2026-06-08

Session theme: **Argo drafts its own fixes.** A short, sharp day: two live bugs
reported over Telegram, two fix PRs — both authored by Argo itself through the
propose-only self-create path (`argo/fix-*` branches), both reviewed and merged by
a human the same evening.

## TL;DR
Two chat-quality bugs went from user report to merged PR without a human writing
the patch. PR #6: replying to one of Argo's messages dropped the quoted text, so
Argo answered without knowing what "this" referred to — fixed by carrying
`reply_to_message` context into the chat turn (`src/argo_reply_context.py`).
PR #7: the word "project" anywhere in a sentence could false-trigger project
generation (disruptive, since a generated project becomes the new current one) —
fixed by tightening the routing guard so only genuine asks route there. Argo
cannot merge its own PRs; both shipped on explicit human review.

## 1. PR #6 — reply context into chat turns
Telegram supplies the quoted message on a reply; Argo ignored it. The fix
extracts the quoted text and threads it into the model turn so follow-ups like
"is this a counter to X?" land with their referent. Authored by Argo via
`propose_change`.

## 2. PR #7 — the routing guard stops guessing
"Project" is an everyday word; treating every mention as "generate me a new
project" hijacked conversations. The guard now requires a real generation intent
before routing to `new_project`, and ambiguous cases ask instead of generating —
consistent with the existing don't-generate-when-unsure rule.

## The honest postscript (found the next day)
PR #6's helper was written, tested, merged — **and imported nowhere.** The reply
context still didn't flow until 06-09 wired it in. The lesson ("a fix must be
wired, not just written") became a standing rule and, two days later, a mechanical
gate: the self-improvement loop's proposal gate now refuses any PR whose new
symbols are never called. The bug that slipped through review on the 8th is the
reason the machine checks for it on the 10th.
